## Aggregate qualitative notes

- ch3 loses type-safety outright: `param(name: string)` catches nothing (README's "'id' is literal-typed" overstates core-v0 — `ParamKey<P>` exists but is not wired into `param()`), `bad-path` compiles and throws only at registration, `query('x')` vs `param('x')` mixups are silent `null`s.
- ch3 wins determinism-adjacent ergonomics: smallest API (3 imports, ~22 avg LOC vs h3's 7.6/22.3), near-zero ways to express a pattern, sync model kills a whole error class — but the same sync model turns the async-handler trap into a process kill + client hang with zero diagnostics.
- ch3's missing surface shows up as **behavioral** losses, not code smell: 404 instead of 405/`Allow` (DESIGN.md §2 promised 405), no `queries()` (workaround needed for arrays — the only task requiring a raw-URL re-parse), no `onError`/`HttpError` (early return is the only error story).
- Runtime precedence is ch3/h3-correct vs hono/express registration-order: `/assets/logo.png` hits the wildcard in hono AND express when `*` is registered first — a real trap for agents who write routes in "most-general-first" order.
- h3 is the ergonomics floor: mounting needs `app.use` + `useBase` (two composed concepts, and the `/**` glob variant of `use` silently does nothing — a real footgun hit during authoring), 7.6 avg imports, alias pairs (`eventHandler`/`defineEventHandler`).
- Express is the sleeper: modern `@types/express` literal-types params from paths — it caught more traps than hono did. Its losses are runtime behavior (HTML 404, registration-order matching, async hang) not compile safety.
- Where the rubric should look next: `ctx.json()` response-shape inference and route-path typing propagation (owner's rubric bullets 3–4) are not yet probed — add expect-type probes in a v1.1.
