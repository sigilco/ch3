# ch3/h3 — h3 API-compat shim

Import surface: `import { ... } from '@sigilco/ch3/h3'` (source: `src/shims/h3.ts`).

**Coverage target:** ~80% of h3 handler usage — `createApp`, `createRouter`,
`defineEventHandler`/`eventHandler`, `H3Event` (`.node.req/.res`, `.context`,
`.path`, `.method`), `useMount`/mount via `app.use(prefix?, router)`,
`toNodeListener`, param/query/body helpers, status/header/cookie helpers,
`send`/`sendError`/`createError`/`isError`, `assertMethod`, `readValidatedBody`
shape pass-through.

## Usage

```ts
import { createApp, createRouter, defineEventHandler, getRouterParam } from '@sigilco/ch3/h3'
import * as http from 'node:http'

const app = createApp()
const router = createRouter()

router.get('/hello/:name', defineEventHandler((e) => {
  return { hello: getRouterParam(e, 'name') }
}))

app.use(router)
http.createServer(app.handler).listen(3000)
```

## Divergences vs upstream h3

1. **Sync-only handlers.** `defineEventHandler` throws
   `"async handlers unsupported under ch3"` at wrap time when
   `h.constructor.name === 'AsyncFunction'`. All `await`-style helpers
   (`readBody`, `getQuery`) are synchronous — calling them without `await`
   returns the value directly.
2. **No nitro lifecycle.** No `app.hooks`, no plugin system, no `useBase`,
   no lazy event handlers (`defineLazyEventHandler`), no `callNodeListener`.
3. **No ws/SSE.** No `defineWebSocket*`/`sendWebSocket*`/`createEventStream`
   utilities.
4. **`setCookie` is last-wins**, not append — scriptc's
   `ServerResponse.setHeader` accepts `string | number` only, so a single
   `set-cookie` line is emitted. `clearSessionCookie`/`appendResponseHeader`
   share the limitation (`appendResponseHeader` comma-joins).
5. **`readBody` parses only on JSON content-type**; otherwise returns the raw
   string (upstream sniffs deeper). Malformed JSON throws `H3Error(400)`.
6. **`event.context` is a per-request bag** shared by all `app.use`
   middleware and the route handler (single-slot keyed on the raw request —
   safe because dispatch is synchronous), not h3's mergeable map.
7. **`app.use(route?, handler)` is a router-level dispatcher**: handlers run
   in registration order until one produces a response; a handler that
   returns `null`/`undefined` yields to the next. No `next()` token arg.
8. **Errors marshal to `{ statusCode, statusMessage?, message, data? }`**
   JSON (not h3's default HTML/plain error page), and unmatched routes get
   `404 Not Found` unless a `use` handler answers.
9. **`createError({...})` maps to `H3Error`** carrying
   `statusCode/statusMessage/message/data/fatal/unhandled` — no
   `stack`-aware formatting, `unhandled` is metadata only.
10. **Core-dependent gaps**: no `HttpError`→`onError` pipeline (core lacks
    an error hook — `sendError`/`writeError` implement it in-shim), no
    `env`/`bodyJson`/`sent` on ctx, `app.use` is emulated over core's
    global-only middleware, response helpers go through `Ctx.header`/`res`.

## Compile note

`scriptc build` as program code (`import '../src/shims/h3.ts'`) currently
hits a latent **core** fence at `src/index.ts:87`
(`ReqView.header`: `v.length` on the `never` branch of
`string | string[] | undefined`). That is a core defect — the shim does not
call `c.req.header` (it reads `event.node.req.headers` directly to sidestep
it). Building the packaged surface
(`scriptc build app.mjs --npm-static @sigilco/ch3`) compiles and serves;
verified with `/hello/:name`, POST echo, and 404.
